7 · 关键经验与坑(避免重蹈)

① 判断"分支健康"必须查 COMMITTED 状态,不能只看 working tree。
本次最严重的一个 bug:auth 改名后 router.dart 的 import 修复只在工作区、忘了 commit,导致已提交的 HEAD 实际 11 个 analyze error 无法编译,而本地 flutter analyze 因为读的是带未提交修复的 working tree 显示"0 错误"。正确做法:git show HEAD:path 看提交态;或在干净 checkout / CI 里验。(flutter test 能过是因为 router 没被测试 import,所以单测绿 ≠ 能编译。)
  • 禁止"假拆分":extension on _State / part of 把代码挪文件但仍共享私有状态 ≠ 拆分。必须是真 Widget / 真 ChangeNotifier / 纯函数,各自可独立测试。
  • 拆一个补一个测试:重构 commit 行为不变,且由测试证明;没测试的重构是赌博。
  • commit 前 git status 必须 clean:本次多次出现 agent"做完忘 commit"或"修复留在工作区",务必收尾确认。
  • 一次 commit 只做一件事:refactor: 不含行为变更;改 API 独立 commit + 同步前端。(refactor-all 的 6 个 checkpoint 是"阶段打包"的例外,细粒度在 wave1-2-full。)
  • GitHub 无 CI:push 不会自动跑测试,所有"绿"目前靠本地验证;后端 mvnw 提交的是 644 无执行位,用 sh mvnw test 跑。
